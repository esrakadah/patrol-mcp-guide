# Contributing

This is a single guide document, not a library, so contribution scope is
intentionally narrow.

## Quick fixes — just open a PR

- Typos, broken links, or stale version numbers.
- A factual correction with a source (a changelog entry, an official doc, a
  release note).

## Anything bigger — open an issue first

- Restructuring a section, adding a new section, or adding a diagram.
- Disagreeing with a recommendation in the guide.

Opening an issue first avoids a large PR landing that duplicates in-progress work
or takes the guide in a direction that doesn't fit its scope.

## Ground rules

- Keep claims verifiable: link a primary source (official docs, a changelog, the
  maintainer's own post) rather than a secondary summary.
- Keep employer/client/project names abstracted, per the guide's existing
  convention (`AppName`).
- Mermaid diagrams should render without custom color styling, so they hold up
  in both GitHub's light and dark themes.
